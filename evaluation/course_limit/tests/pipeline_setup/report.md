# 流程測試（pipeline_setup）：選課上限題，用假設的答案讓整條評測管線跑一次

**日期**：2026-11-11（同日第二輪：依第一輪發現重建 gold 後，重做判斷與算分）
**這不是系統的真實答案，下面的分數不能當評測結果。** 目的只有兩個：檢查整條管線在第一題非聯絡人題上走不走得通，以及找出判斷規則的灰區。
答案是 Claude Code 寫的（`answers/`），證據用 `sources/snapshot/` 裡真實的頁面原文（學則、FAQ、選課須知）包成 `get_page` 工具輸出的樣子，`model`／`system_version`／`label` 都標「假設」。
不放 `runs/`，所以 `list_runs.py` 與之後的彙整都讀不到。`make_runs.py` 沒有單元測試。

## 灰區的處理結果（使用者逐項決定）

### 1. K2、K5 各含兩個事實 → 已拆成單一事實

K2（雙主修 31、輔系 28）拆成 K2、K3；K5（下限 12、10）拆成 K6、K7，共 7 個 keypoint。拆了之後，只講一半就只得一半，一半對一半錯不再連累對的主張，上面的比較表就是驗證。
現有的合併引句兩個 keypoint 共用，沒有新增原文。

### 2. 規則版被換個說法誤判 → 縮小規則版的範圍

規則版是字串比對（答案裡有沒有出現清單中的字串），文字敘述換個說法就會誤判，補字補不完。決定：**數字型 keypoint（K1、K2、K3、K6、K7）設 `hard`**，規則版判斷，清單只收數字的寫法（「25學分」「二十五學分」「25個學分」）；**文字敘述型（K4 超減修、K5 碩博士自定）設 `semantic`**，只交給階段 3 的 Keypoint 判斷，不再維護寫法清單。
範例：答案寫「由各系（所）自行訂定」，舊的 K4 規則版判 miss，現在 K5 是 semantic，由 Claude 判 relevant，不再有不一致。
仍有的限制：數字也可能被換個說法漏掉（例如「25 個學分」要靠清單補「25個學分」）；規則版只是便宜的第二意見，不是主要結果。

### 3. 推論與否定句 → 交給 LLM 判斷，記為已知限制

主張「沒有全校統一的上限」，證據只寫「由各系(所)自定」，沒有逐字寫這句。`complete` 與 `wrong` 兩個**獨立**子代理都判 supported，也都在 `why` 自述「屬直接推論」。決定：不改回推規則、不改格式，由子代理自行裁量，`why` 欄位保留它的說明。
限制：不同子代理對推論句可能判得不同；兩個子代理一致只是小樣本。
相關的 gold 原則：gold 是抽取不是生成，沒有逐字原文的推論不列入，所以 K5 只寫「由各系（所）自定」，拿掉「沒有全校統一的上限」。
連帶效果：這句推論 c9 不連到任何 keypoint，所以以主張為單位的精確率被拉低（`complete` 是 8÷9＝0.89 而不是 1.00）：答案多說了標準沒有的內容，精確率就會降，是這個指標原本的行為。

### 4. 非聯絡人答案的切法（初步觀察，沒有決定）

- 切得比預期細：`complete` 的 4 段文字切成 9 個主張，每個事實一個，在逗號處分開；沒有重疊；規則 7（人員行）沒有用到。
- 條件與結果被分成兩個主張：「經系主任核可，可在當學期申請超修或減修學分」（c6）與「超減修最多以 6 學分為限」（c7），兩者都連到 K4。
- 片段會失去主語：c2「第一至第三學年每學期不得少於 12 學分」沒有「學士班學生」。
- 答案是我寫的、比真實答案整齊，這些只是趨勢；真實的 Gemma 答案要等有 run 才知道。

## 限制

- 答案、Keypoint 判斷都是 Claude Code 做的，我知道哪裡是故意寫錯的，判斷**不獨立**；這個測試只驗證機制，不驗證判斷品質。
- 證據是我挑的三頁，不是系統自己檢索的；檢索漏斗（頁面→清單→答案）沒有測。Context 句子的精確率 0.010、詞 0.028 只是因為整頁（學則 13,216 字）都算進去，沒有意義（設計上本來就只供比較）。
- 每個案例一個子代理、一次執行；LLM 每次輸出不同。
- 子代理只查了工具呼叫，看不到推理；只查這一次。

## 後續

- 等有真實 run 之後，再看非聯絡人答案的切法，決定要不要為這一類題型寫切法指引。
- 其他題的 gold 照這一題的經驗做：一個 keypoint 一個事實；數字型 `hard`、文字敘述型 `semantic`。
