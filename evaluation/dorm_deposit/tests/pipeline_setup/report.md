## 發現

1. **順序錯誤只有 Keypoint 判斷能抓到，而且抓得到**：`wrong_order`（先住宿組、之後才檢查寢室）與 `skip_desk`（直接到住宿組）都把 K3（先檢查寢室簽章，之後才到住宿組）判 wrong。規則版對順序完全無感（K3 是 semantic），這題的順序全部靠判斷版，所以鏈式題比其他題更依賴它。
2. **專門的順序 keypoint 有用**：`wrong_order` 的回推把「先到住宿組，之後再請宿舍服務台檢查寢室」切成 3 個主張（c4–c6），順序資訊散在三個主張裡；如果沒有 K3，這個錯誤只會表現成幾個主張無依據，看不出是「順序顛倒」。（維持使用者的決定：不改切法，用專門的 keypoint 考順序。）
3. **「答對但沒依據」又出現（`complete` 的 K17、K21；`wrong_order` 的 K2）**：
   - `complete`：「大學部洽陳哲良（分機 62222）、研究所洽曾偉哲（分機 63251）」被回推判 unsupported，因為證據只有人員清單，沒有「大學部／研究所」的分工，那句話在學務處退費頁（假設證據沒放）。K17、K21 判斷版都是 relevant。
   - `wrong_order`：「辦理退宿，之後再請宿舍服務台檢查寢室」一個主張混了對（有請服務台檢查寢室）與錯（順序顛倒），整個判無依據，K2 變成「答對但沒依據」。與第 7 題同一類（議題 F2，切法）。
4. **沒有發現新的程式問題**：表單連結、住宿組與出納組聯絡人與樓層、條件式（僑外生、出納組不提不適用）都照預期運作。`complete` 的 K22（提到出納組卻沒寫出納組聯絡人）判 miss：這是條件式規則的設計（答案提到出納組，就要寫聯絡人）。
