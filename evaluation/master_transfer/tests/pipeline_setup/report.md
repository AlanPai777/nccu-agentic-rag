# 流程測試（pipeline_setup）：碩士班轉系所需要經過哪些單位同意（並行雙處室，29 個 keypoint），用假設的答案讓整條評測管線跑一次

**日期**：2026-11-13
**這不是系統的真實答案，下面的分數不能當評測結果。** 目的：檢查「兩個系所並行同意，再送教務處」這種並行雙處室題走不走得通。
答案是 Claude Code 寫的（`answers/`）。證據：教務處「轉系／轉所」頁面與兩張表單（QP-T01-05-05、QP-T01-05-06）的快照原文，加註冊組的聯絡資訊（假設，用登記表排的）。**學則不在證據裡**（系統不一定會讀學則）。不放 `runs/`。`make_runs.py` 沒有單元測試。

## 發現

1. **「兩邊都要同意」可以靠語意 keypoint 抓到**：`wrong_facts` 寫「不需要轉入系所同意」，K2（轉入系所同意）判 wrong；`one_side` 同樣漏掉轉入系所，用判斷版會判 K2 irrelevant。這題的核心是 semantic，規則版只管表單編號、連結、註冊組，所以這題更依賴 Keypoint 判斷。
2. **日期用 semantic 行得通**：`live_names` 寫「十二月整個月」「六月整個月」，判斷版判 K10、K11 relevant；用 hard 的話這種寫法會被判成沒提到。日期寫錯（12/15 取代 12/31）判 wrong。
3. **「答對但沒依據」（`complete` 的 K21）**：名額「一成」只在學則裡，假設證據沒有學則，所以 c28 沒有依據。真實 run 要看系統有沒有讀學則。
4. **主張的切法會影響「有依據」比例（`wrong_facts`）**：「要先經原就讀系所同意，再由教務處核准就可以了，不需要轉入系所同意」被切成一個主張（c1），一半對一半錯，整個主張判 unsupported，但 K1（原系所同意）仍判 relevant、K2 判 wrong，所以 K1 變成「答對但沒依據」。這是回推規則「一個主張只講一件事」的灰區（與議題 F1、F2 同類），沒有新發現，只多一個實例。
5. **`complete` 的「不是先後關係」（c2）無依據**：這是回答額外的解讀，表單與頁面沒有這句話；它沒有對應的 keypoint，所以不影響 Completeness，只讓有依據比例降到 0.93。「並行」是我們設計文件的說法，原文只寫「經原肄業所及擬轉入所雙方主管同意」。
6. **沒有發現新的程式問題**：表單連結（條件式的學分認定申請書連結）、註冊組聯絡人與樓層、日期 semantic 的判斷都照預期運作。
