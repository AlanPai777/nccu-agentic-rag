**日期**：2026-11-13
**這不是系統的真實答案，下面的分數不能當評測結果。** 目的：檢查整條管線在第一題跨處室、引用登記表的題目上走不走得通，並找出這類題目特有的問題。
答案是 Claude Code 寫的（`answers/`）。證據：教務處頁面與三張表單用 `output/` 的真實快照；**辦公室聯絡資訊那一則是假設的**（用 `evaluation/registry/registry.json` 照 `contact_node` 的版面排出來，名字取快照寫法），不是真實 run 的輸出。`model`／`system_version`／`label` 都標「假設」。不放 `runs/`。`make_runs.py` 沒有單元測試。

## 發現

1. **寫錯樓層與名字配錯分機都抓得到（`wrong_pairs`）**：K2（時限）、K15（王揚忠 63274）、K17（盧誼甄 62224）、K18（生僑組二樓）都判 wrong，規則版與判斷一致；國合處沒提到，K19、K20 與委託書 K7 都不適用、不計入。
2. **流程測試找到並修好兩個程式問題**：（a）樓層比對範圍只有前後 40 字，完整答案裡生僑組後面接了一長串文件說明，樓層被判 miss；現在改成同一行或前後 40 字，同一行提到別的單位時只看 40 字內；（b）「盧小姐 62226」被錯判成國合處盧小姐（62833）的錯誤；現在只要有人能用這個寫法且分機相符，就不算錯。另外寫了別的樓層改判 wrong。這三處都補了單元測試（`evaluation/tests/test_registry.py`）。
3. **K1 的「選課上課」在證據裡沒有依據（`c2` 三個案例都 unsupported）**：gold K1 的標準是「期滿者完成繳費註冊、選課上課即完成復學」，「選課上課」只有註冊通知單 115-1 寫，教務處頁面只寫「繳費註冊」。假設的證據只有教務處頁面與表單，所以這半句沒有依據。**待決定**：把 K1 拆成「期滿復學要依規定期限繳費註冊」（教務處頁面也有，必要）與「完成繳費註冊、選課上課即完成復學手續」（只有通知單，選擇性），符合一個 keypoint 一個事實；或者保留，接受系統沒讀通知單時 K1 的主張無依據。
4. **「答對但沒依據」（`live_forms` 的 K17）**：答案寫「盧小姐（分機 62226）」，登記表與規則版認為對（現場頁寫姓氏加稱謂是合法寫法），但假設證據用的是快照全名（盧誼甄），裡面沒有「小姐」，回推判 unsupported。這是預期的行為，不是程式問題：系統讀到哪個來源，主張才有依據；真實 run 如果讀的是現場頁，證據裡會有「小姐」。報告要把 `K17` 這種情況單獨列出（`scores.json` 已有「答對但沒依據」）。
5. **`K12` 的灰區**：`wrong_pairs` 寫「再由註冊組承辦人與組長蓋章」，沒寫「擬准」，判 relevant（最重要的資訊一致）。如果要求一定要有「擬准」，K12 要再拆。
6. **表單表格裡的字是逐字隔開的**（「系 所 會 辦」「註 冊 組 組 長」）：回推的子代理照原樣引用，程式的空白正規化可以對上，沒有問題。子代理回報這幾處比較沒把握，是因為要引用隔開的字。
7. **假設證據的限制**：辦公室聯絡資訊是用登記表排的，真實的 `contact_node` 對國合處讀的是舊索引，沒有姓名（議題 F15）；所以這份測試沒有測到「系統答不出國合處人名」的真實情形，那要等真實 run。
