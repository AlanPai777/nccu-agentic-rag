## 與上一版比

- **重疊**：v1 有 3 個主張被較長的主張包含（c7、c9、c11，例如同時列出「劉桂芬（組長）」與「劉桂芬（組長）分機 62123」），v2 是 0 個。
- **拆分**：v1 把人員行拆成「姓名職稱」與「分機」兩個主張，v2 每個人一個主張（姓名、職稱、分機在一起）。v2 的 10 個主張是：電話、分機、傳真、樓層、辦公時間、職掌、四個人各一行。
- **為什麼這樣**：這是規則 7 與規則 9 的直接結果，不是意外的改善；它說明新規則有被遵守，不說明回推比以前更準。
- **抓到的錯誤**：6 個植入錯誤的抓法與 v1 相同，原因的說明也正確（傳真 4784、5 樓、證據沒有辦公時間與職掌、62123 屬於另一人、林瓊蓮是兼任助理）。
- **代價**：主張變粗之後，T9 這種「姓名與分機都對、只有職稱錯」整行被標一個 unsupported，看不出是哪一部分錯；`why` 欄位有寫明（「證據中林瓊蓮的職稱是兼任助理」），但主張本身沒有拆開。
- **有依據比例**：4÷10 = 0.40。v1 是 5÷11（約 0.45）。兩者的主張切法不同，**不能直接比較**，只是記下來。

## 限制

- 一個子代理、一次執行、一份答案。LLM 每次輸出不同，一次全抓到不代表下次也會。穩定度沒有測（使用者決定先不考慮）。
- 子代理的工具呼叫已用 `audit_subagent_tools.py` 查過（`results/run1/tool_audit.json`）：3 次，Read 輸入檔、Write 輸出檔、交回報告，沒有越界。限制：只查動作，看不到它的推理；只查這一次，不保證下一次。v1 沒有做這項檢查，所以這是 v2 多出來的證據，不是兩版的差別。
- 這份改壞答案測不到的：答案長得很不一樣、證據是整頁網頁而不是聯絡清單的情況；規則 8（網址裡的字不算證據）在 v2 的證據裡沒有機會被用到，因為來源行已經剝掉。
- T5 與 v1 不可比，所以「v1 與 v2 的 T5 都抓到」不能解讀成同一能力的重複驗證。
