# Question 005 — 政大學生跨校修讀台聯大雙主修需要經過哪些單位審核

**Date:** 2026-09-18
**Pipeline:** `agentic_rag.py`（Gemma4:31b-cloud via Ollama Cloud）
**架構模式：** 跨處室 — 跨機構（兩校各自的主修/加修學系 + 註冊組兩層簽核）
**Criteria:** `rag/eval_criteria/consortium_double_major.py`（`EVAL_CRITERIA_CONSORTIUM_DOUBLE_MAJOR`，7 項 × 2 = 14 分）

## 方法論

Sonnet 直接讀 `output/aca/extracted_supplementary.jsonl` 裡 `QP-T01-04-21`（台灣聯合大學系統學士班學生跨校修讀輔系雙主修申請表）表單原文查證，非查記憶。

## 表單原文關鍵段落

```
台聯大跨校修讀輔系及雙主修之上限(含校內輔系及雙主修)為一個雙主修及二個輔系。
加修校系：國立中央大學 / 國立政治大學 / 國立清華大學 / 國立陽明交通大學

簽核流程：
  原就讀學校 → 主修學系[承辦人+單位主管] → 註冊組[承辦人+組長]
  加修學校   → 加修學系[承辦人+單位主管] → 註冊組[承辦人+組長]

若申請外校雙主修通過，則自願自動放棄現正修習雙主修資格。
若申請外校輔系通過，則自願自動放棄現正修習輔系資格。
```

## Gold Standard 答案

政大學生跨校修讀台聯大（中央/清華/陽明交通）輔系或雙主修，需經兩校各自兩層審核：(1) 政大主修學系同意 → 政大註冊組承辦人+組長；(2) 加修學校加修學系准予修讀 → 加修學校註冊組承辦人+組長。跨校修讀上限（含校內）為一個雙主修及二個輔系，一旦外校申請通過即自願自動放棄現有同類資格。

## 系統實際輸出

**總分：3/14**

檢索路徑：`search_texts('跨校雙主修 審核單位')` 命中 `aca` 子網域「跨校雙輔」頁面（judge：「候選頁面1明確提及『台聯大跨校修讀雙主修輔系專區』，與問題中的跨校修讀程序完全匹配」），`get_page_tool` 抓取後 3 輪內收斂。

先確認語料庫裡確實有大量台聯大專屬內容才排除「資料本身缺」的可能：`output/aca/extracted_texts.jsonl` 裡有 `QP-T01-04-21` 表單本身、至少 4 篇不同學年度的台聯大跨校雙主修/輔系申請公告、「台灣聯合大學系統學生跨校修讀雙主修/輔系辦法」PDF——資料是齊的，是 `search_texts` 的候選判斷（judge）把「主題詞相同但機構不同」的頁面誤判為匹配。

## 根因定位（judge 誤判的具體位置）

candidate 頁面第一行其實是一個**超連結**，文字是「台聯大跨校修讀雙主修輔系專區」，連到另一個頁面（`專區業務/newbie-2/150-跨校修讀雙主修輔系/4963-...`），但這個候選頁面本身從沒有真的被點進去讀——接下來整頁內容講的都是北藝大。judge 的通過理由寫的是：「候選頁面1明確提及『台聯大跨校修讀雙主修輔系專區』，與問題...完全匹配」——**judge 只看到「台聯大」三個字出現在一個連結的錨點文字裡，就判定整頁內容匹配，沒有核對這幾個字其實只是指向別處的連結標籤，也沒有比對頁面主體內容跟查詢裡點名的機構（中央/清華/陽明交通）是否一致。**

**結果一致：3/14，同一份「跨校雙輔」（北藝大）頁面再次被 judge 通過**，排除單次取樣偶然。但這次額外浮現一個更嚴重的細節——這次 synthesis 生成的答案第一句直接寫「政大學生申請跨校修讀**台聯大（以臺北藝術大學為例）**雙主修或輔系」，第三步標題也寫「**台聯大（北藝大）**審查與結果公告」。**國立臺北藝術大學從來不是台聯大（中央/清華/陽明交通/政大四校聯盟）的成員校**，這不是單純選錯文件而已——synthesis 主動在答案裡建立了一個不存在的從屬關係（把北藝大講成「台聯大的例子」），這比「答錯合作對象」更進一步，是**捏造兩個真實實體之間一個不存在的關係**，性質上更接近幻覺，不只是檢索誤判的被動結果。

## 修正（2026-09-18）

**採用方式**：使用者明確要求不要用針對這一題寫的 prompt 規則去修（曾嘗試在 `_JUDGE_PROMPT` 加一條「具名對象核對」規則，被要求撤回），改在資料層做通用修正。根因是候選頁面的判官（`_judge_candidates`，`rag/agentic/logic/rewrite.py`）看到的 200 字摘要裡，「台聯大」三個字只存在於頁面開頭一個**連結的錨點文字**（`[台聯大跨校修讀雙主修輔系專區](另一個網址)`）裡，這個連結指向的是完全不同的頁面，但錨點文字跟頁面本身的內容在摘要裡混在一起，judge 沒辦法分辨。

**修正內容**：新增 `_strip_md_links()`（`_MD_LINK_RE = re.compile(r"\[[^\]]*\]\([^)]*\)")`），在 `_judge_candidates()` 組出候選清單摘要前，先把候選頁面裡完整的 markdown 連結（錨點文字+網址）整段拿掉，只留頁面自己的正文再截 200 字給 judge 看。這是通用的資料層修正——任何候選頁面只要有「開頭放一個指向別處的連結、連結文字剛好跟查詢用詞重疊」的結構都會受益，不是針對「台聯大」寫的特殊規則，也完全沒改動 `_JUDGE_PROMPT` 本身的任何文字。`get_page_tool` 實際抓取頁面全文時仍保留完整連結（agent 才能追蹤真正的表單/頁面），只有判官看到的摘要被清理。

## 結論

**已修正並驗證，不再是「答錯合作對象」等級的缺陷。** 根因是 judge 只做表面文字比對、把連結錨點文字當成頁面本身內容看待，不是「LLM 無法判斷哪份文件對」這麼籠統的說法——精確定位到是候選摘要的資料層有噪音（連結錨點文字混入頁面內容判斷），用決定性的方式（regex 拿掉整個連結）清理掉這個噪音，不需要教 LLM 一條新規則就讓既有 judge prompt 自然判斷得更準。9/14 剩下的 3 項缺漏（用詞、校名、上限數字）性質上比較接近前四題已經記錄過的「細節缺漏/用詞問題」，不再是本題最初發現的「選錯整個對象」等級的系統缺陷。
