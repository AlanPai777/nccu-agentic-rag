# Question 002 — 搬離宿舍如何辦理退還住宿保證金

**Date:** 2026-09-18
**Pipeline:** `agentic_rag.py`（Gemma4:31b-cloud via Ollama Cloud）
**架構模式：** 跨處室 — 鏈式依賴（宿舍檢查 → 三天內住宿組辦理，第二站需要第一站的結果）
**Criteria:** `rag/eval_criteria/dorm_checkout.py`（`EVAL_CRITERIA_DORM_CHECKOUT`，6 項 × 2 = 12 分）

## 方法論

Sonnet 直接讀 `output/osa/extracted_texts.jsonl`（「退離宿程序」頁面）與 `output/osa/extracted_supplementary.jsonl`（`QP-M03-01-05` 表單原文）查證，非查記憶。

## Query 演變（重要）

原始 query「如何辦理退宿」天生模糊，對應兩種互斥情境：
1. 學期前退宿（未進住/取消續住，`QP-M03-01-04`，不涉及保證金）
2. 離宿暨退還保證金（學期中/末搬離，`QP-M03-01-05`，本題實際要測的鏈式依賴）

**第一次實測（模糊版 query）**：`search_texts('退宿')` 只找到 `QP-M03-01-04`，judge 直接通過收斂作答，全程只讀一份文件，**從未探索保證金退還這條分支**。答案對它讀到的範圍完全正確、無幻覺，但對「退宿」的完整涵蓋度不足——這是真實的 KNOWLEDGE 路徑缺口（找到第一個看似合理的候選就停，未確認涵蓋度；同 CLAUDE.md Known issues 記錄的既有模式），**不是這批 criteria 該修正的對象**，而是值得記錄的獨立發現（見下方「模糊查詢的獨立發現」）。

因此把 query 改為明確指名「保證金」的版本，只對應情境 2，重新測鏈式依賴本身。

## 表單原文關鍵段落（QP-M03-01-05）

```
離宿流程：宿舍區管理人員檢查寢室 ➔ 三天內至住宿組辦理退費(持本表及宿費收據)
注意：1. 僅退住宿保證金者可不交宿費收據；「宿費繳費收據」若遺失，可請出納組補發。
     3. 僑生及外籍生因離宿後即出國、帳戶已結清無法領取者，另再填『僑外生退住宿保證金轉入代領人帳戶領據』
        辦理，外籍交換生請向相關系所辦理退還「住宿保證金」。
```

## Gold Standard 答案

先由宿舍管理人員檢查寢室，三天內持已檢查的申請表（`QP-M03-01-05`）及宿費收據（僅退保證金者可免附）至住宿組辦理，款項匯入學生登記帳戶；僑生/外籍生若已出國無法領取需另填委託書，外籍交換生則向所屬系所辦理。

## 系統實際輸出

### 第 1 次（改用明確 query 後）

**總分：9/12**，扣分：`dorm_desk_checkin`（0/2）、`housing_office_deadline`（1/2）。

檢索路徑：`search_texts('住宿保證金退還')` 一次命中 `QP-M03-01-05`（judge：「該頁面明確提及『離宿暨退還保證金申請表』及具體的『退費流程』，與問題完全匹配」），3 輪內收斂。

人工核對答案內容：完整涵蓋寢室檢查 → 3天內住宿組 → 退費方式 → 僑生/外籍生/交換生三種身分各自的處理方式，甚至正確答出 criteria 沒要求的細節——「僅申請退還保證金者不需交宿費收據」「扣款超過1000元需追繳」，無幻覺。**答案本身正確完整**，扣分原因查證後發現是 criteria 用詞問題：
- `dorm_desk_checkin`：答案用的是表單原文「宿舍區管理人員檢查寢室」，不是我原本從另一份頁面（退離宿程序）抄來的「宿舍服務台」——兩份文件對同一步驟用了不同措辭，criteria 只認後者。
- `housing_office_deadline`：答案用阿拉伯數字「3 天內」，criteria 只認中文數字「三天內」。

### Criteria 修正

- `dorm_desk_checkin` keywords 加入「宿舍區管理人員」「檢查寢室」「寢室檢查」。
- `housing_office_deadline` keywords 加入「3天內」「3 天內」（同 `refund_table` 早已接受「2/3」與「三分之二」兩種格式的既有做法）。

修正後對同一份（未重新生成的）答案文字離線重新計分：**12/12**。

## 模糊查詢的獨立發現（不掛在 QUERY_CRITERIA_MAP，僅記錄）

Query「如何辦理退宿」：agent 只搜尋一次、找到第一個候選（`QP-M03-01-04`，學期前退宿）就收斂作答，完全沒有探索「離宿暨退還保證金」（`QP-M03-01-05`）這一半同樣合法的情境，`self_eval_node` 也沒有攔下這個不完整（未觸發 `[self_eval提醒]`）。答案對它涵蓋的範圍是正確、有憑有據的（真實聯絡人、正確退費比例表），**不是幻覺**，但對這個模糊查詢的完整涵蓋度不足。歸類：KNOWLEDGE 路徑「找到第一個候選就停」的已知失敗模式（CLAUDE.md Known issues）在跨處室情境下的一個新實例。

## 結論

**Criteria 已修正並驗證（12/12）。** 這題示範了本輪驗證方法論最重要的一課：分數低不等於答案錯，要看完整輸出人工判斷——本題兩次扣分都是「答案對、criteria 用詞太窄」，跟 `refund_table` 當初要同時接受中文/阿拉伯數字格式是同一類問題，不是新問題。同時，原始模糊版 query 意外挖出一個真實的檢索涵蓋度缺口，獨立記錄保留，不影響本題最終 criteria 的判定。
